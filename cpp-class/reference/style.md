# Tsukini C++ style (reference)

Extracted from the most recent files of libutils (`IdHandler`, `Scheduler`, `ArgParser`,
`ISocket`/`ASocket`, `ArgParserType`, `NetworkDefine`) and the nvim config
(`~/.config/nvim/lua/header/xartania.lua`, `function/basic.lua`, `basics/options.lua`).
The files in `../examples/` are the ground truth: when this document and an example
disagree, follow the example.

## Formatting
- 4 spaces, never tabs, UTF-8, no trailing whitespace (the banner lines are the exception).
- Function/method bodies defined out of line: opening brace **on its own line**.
- Class, struct, enum, namespace, `if`, `for`, `while`, lambda: brace **on the same line**.
- One-liners: no inner spaces and a `;` after the closing brace:
  `_cold _nodiscard int getFd(void) const {return this->_fd;};`
- Long inline body that doesn't fit on one line: the brace goes on the next line, same indent as the method.
- Empty parameter list is always written `(void)`.
- Member access always through `this->`.
- `for (const auto& x: list)`, `class A: public B`: no space before `:`.
- References/pointers glued to the type: `const std::string& name`, `char* buf`
  (exception kept from the code: `const char *const argv[]`).
- Short `if` can stay on one line: `if (safe_mode) lock.lock();` / `else (void)lock.try_lock();`.
- Discarded results are casted: `(void)cv.wait_for(...)`.
- Empty bodies: `/* Nothing */`.
- Structured bindings: `const auto &[fid, flag]: this->_flags`, unused parts named `_`.

## File header
Generated by `scripts/header.py` (never written by hand). Box of 64 chars, optional
ANSI Shadow banner (each line prefixed by one space), then:
```
Edition:
##  @date DD/MM/YYYY by @author Tsukini

File Name:
##  @file Name.hpp

File Description:
##  <one line description>
```
Default description (when there is nothing meaningful to say, typically in a .cpp):
`You know, I don t think there are good or bad descriptions,` / `for me, life is all about functions...`

## .hpp layout
```
<header>

#ifndef NAME_H
    #define NAME_H

    //----------------------------------------------------------------//
    /* INCLUDE */

    /* type */
    #include "../attribute/Attribute.hpp"   // _cold, _hot
    #include <vector>                       // std::vector

    //----------------------------------------------------------------//
    /* DEFINE */          (only if needed, indented like the includes)

namespace a::b { // namespace start
//----------------------------------------------------------------//
/* PROTOTYPE */          (forward declarations, free functions)

//----------------------------------------------------------------//
/* ENUM */ /* STRUCT */ /* CLASS */

} // namespace end

//----------------------------------------------------------------//
/* MIGRATION */          (only for deprecated aliases, _migration(x, y, z))

#endif /* NAME_H */
```
- Guard = file name in upper case without separator + `_H` (`IdHandler.hpp` -> `IDHANDLER_H`,
  `ArgParserType.hpp` -> `ARGPARSERTYPE_H`). `#define` is indented by 4 spaces.
- Section separator: `//` + 64 `-` + `//`, followed by `/* SECTION */`.
- Includes, inside a header:
  - project files first, with a **relative** path (`"../../attribute/Attribute.hpp"`, `"ISocket.hpp"`),
    then the STL;
  - roughly sorted from the longest line to the shortest (staircase);
  - each one has a trailing comment, **aligned** on the same column, listing what is used
    (`// std::mutex, std::unique_lock`).
- Namespace = folder path under `include/` (`include/utils/system/X.hpp` -> `utils::system`).
  Types used from the project are always fully qualified (`utils::exception::ErrorException`),
  no `using namespace`.
- Free functions in `/* PROTOTYPE */`, grouped under small `/* group */` comments,
  with a trailing comment explaining them.

## Class layout
Visibility order: `private` (or `protected`) **first**, then `public`.
Inside each visibility, in this order (omit the empty blocks, except Operator/Constructor/Destructor):
```
        // ---------- Pre-Function -------- //   declarations only (defined in the .cpp)
        // ------------ Function ---------- //   defined inline in the header (templates, one-liners)
        // ------------ Operator ---------- //
        // ---------- Constructor --------- //
        // ----------- Destructor --------- //
```
- Members first (before the blocks), `_camelCase`, default value at the declaration
  (`int _fd = -1; // -1 = closed`), grouped under `/* group */` comments when there are many.
- Sub-groups inside a block: `/* setup */`, `/* setter */`, `/* getter */`, `/* raw */`, `/* parsing */`...
- Methods `camelCase`; a private implementation behind a public wrapper gets a trailing `_` (`allocate_`).
- Getters `getX(void) const`, setters `setX(...)`, resets `resetX(void)`.
- Default rule of five (unless the class needs otherwise):
  ```
  // ------------ Operator ---------- //
  X& operator=(const X& other) = delete;
  X& operator=(X&& other) = delete;

  // ---------- Constructor --------- //
  X() = default;
  X(const X& other) = delete;
  X(X&& other) = delete;

  // ----------- Destructor --------- //
  ~X() = default;
  ```
- Trailing `//` comment on declarations to explain the behavior or default values.
- `static_assert` right after the class opening for template constraints.
- Thread safety pattern: `mutable std::mutex _lock; // Handling of multithreading` with a
  `const bool safe_mode = true` parameter (see `IdHandler.hpp`).

## Naming / hierarchy
- `IName`: interface, every method `virtual ... = 0`, `virtual ~IName() = default;`, `protected` then `public`.
- `AName`: abstract base, `public IName`, implemented methods marked `final` (or `override` when a
  child may redefine), `protected` members.
- `Name`: concrete class.
- `NameType.hpp`: `/* STRUCT */` + `using` aliases. `NameDefine.hpp`: `/* DEFINE */` macros
  (`UPPER_CASE`, trailing comment) + `/* ENUM */` `enum class` (PascalCase values, trailing comma).
- Template class: everything in the .hpp (no .cpp).

## .cpp layout
```
<header>

#include "utils/attribute/Attribute.hpp"
#include "utils/exception/ExceptionDefine.hpp"
#include "module/Name.hpp"
#include <algorithm>
#include <string>

_hot void ns::Name::method(void)
{
    std::lock_guard lock(this->_lock);

    // Short comment above each logical block
    ...
}
```
- Includes: project ones first with the path **from `include/`**, then the STL, no comments.
- No `namespace x {}` block: every definition is fully qualified (`void utils::system::Scheduler::clear(void)`).
- Constructor init list on its own line: `: _binary{binary}, _description{description}`.
- Comments: short, English, above the block they describe, starting with an uppercase letter.
- Early returns for trivial cases: `if (this->_finished.empty()) return;`.

## Errors
- With libutils: `throw utils::exception::ErrorException(utils::exception::InternalCode::X, "msg");`
  (`FatalException` for unrecoverable, `WarningException(...).formated()` printed on `std::cerr` for warnings).
- Without libutils: standard exceptions (`std::runtime_error`, `std::invalid_argument`...),
  or the project's own exception classes if they exist.

## Attributes
`scripts/detect_libutils.sh <project>` decides:

| libutils macro | standard attribute (mode `std`) |
|---|---|
| `_hot` | `[[gnu::hot]]` |
| `_cold` | `[[gnu::cold]]` |
| `_nodiscard` | `[[nodiscard]]` |
| `_unused` | `[[maybe_unused]]` |
| `_likely` / `_unlikely` | `[[likely]]` / `[[unlikely]]` |
| `_fallthrough` | `[[fallthrough]]` |
| `_noinline` | `[[noinline]]` (`[[gnu::noinline]]` for gcc) |
| `_deprecated(info)` | `[[deprecated(info)]]` |
| `_noaddress` | `[[no_unique_address]]` |
| `_packed` | `[[gnu::packed]]` |
| `_assume(expr)` | `[[assume(expr)]]` |

- `internal` (inside libutils): macros + `#include "../attribute/Attribute.hpp"` (relative) in headers,
  `"utils/attribute/Attribute.hpp"` in .cpp.
- `libutils`: macros + `#include "utils/attribute/Attribute.hpp"` (comment aligned like the others).
- `std`: standard attributes, no Attribute include. Placement stays the same
  (`[[gnu::cold]] [[nodiscard]] int getFd(void) const {return this->_fd;};`,
  `if (...) [[unlikely]] {`).
- Usage: `_hot` on hot paths (alloc, send, compute), `_cold` on setters/getters/setup/cancel,
  `_nodiscard` on every getter or function whose return value matters, `_likely`/`_unlikely`
  after the condition of an `if`/`else`.

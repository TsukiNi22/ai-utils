# libutils reference

**Version of this reference: read `reference/VERSION.md` first** (version, commit hash, date).
Everything below `reference/` is generated by `scripts/gen_api.py` from that exact commit.
`SKILL_DIR` = the directory of this file, `LIBUTILS` = `~/personal_delivery/cpp/libutils`.

## Freshness check (first, once per conversation)

`libutils-setup`, `libutils-install`, `cpp-class`, `cpp-project`, `audit-bugs`), run
`bash SKILL_DIR/scripts/check.sh` (local, fast; `--fetch` also compares with `origin/main`; same as
`xstyle --libutils-check`). Last line:
- `status: up to date` -> go on;
- `status: unknown` (no repository, nothing installed) -> go on, say it once;
- `status: outdated` -> **if the user already answered this question earlier in the conversation, apply that answer
  again without asking**; otherwise ask once (AskUserQuestion, French, `multiSelect: true`), then remember the answer
  for the whole conversation. The updates are done **by the matching skill**, never by hand:
  | Choice | Done by |

  | `Continuer avec la référence actuelle` (alone) | nothing; say once that the newer APIs / renames may be missing |
  | `Mettre à jour libutils installé` | the **`libutils-install`** skill (`libutils.sh update`, root asked by that skill, then `status`) |
  | `Mettre à jour la version requise par le projet` (only in a project using libutils) | the **`libutils-setup`** skill (`setup_project.py <root> --version <installed version>`: `find_package(utils X.Y.Z)` bumped, rebuild) |

  Pre-select from the lines of `check.sh`: `installed: ... (differs)` with an installed version older than the reference

## How to answer a libutils question
1. `reference/index.md`: find the section / header / namespace of what is needed
   (one table per section, small enough to read entirely).
2. `reference/api/<section>.md`: public API of the headers of that section (signatures,
   default values, trailing comments = documentation). Read only the needed section.
3. Error codes: `reference/exception-codes.md`.
4. Real usage examples: the unit tests of the same commit,
   `git -C LIBUTILS show <commit>:tests/<section>/<file>` (`git -C LIBUTILS ls-tree -r --name-only <commit> tests`),
   and the wiki https://github.com/TsukiNi22/libutils/wiki.
5. Only if the answer is not in the reference: read the header itself at the commit
   (`git -C LIBUTILS show <commit>:include/utils/<path>`) for the implementation details.

## Version checks
- The project may use another version than the reference:
  - required version: `find_package(utils <version> CONFIG REQUIRED)` in the project `CMakeLists.txt`;
  - installed version: `grep __LIBUTILS_VERSION__ /usr/include/utils/version.hpp /usr/local/include/utils/version.hpp`;
  - at runtime: `utils::version` (`std::string_view`, `"vX.Y.Z"`).
- If the version differs from the reference, check the differences before advising an API:
  `git -C LIBUTILS diff --stat v<installed> <commit> -- include` and the CHANGELOG between both
  (removed/renamed APIs are listed in `### Removed` / `### Changed`, migrations keep the old name with a
  `[deprecated ~vX.Y.Z]` marker in the reference).
- New things since the reference: `bash SKILL_DIR/scripts/update.sh --check` (commits, changed headers,
  new CHANGELOG lines since the recorded hash). `bash SKILL_DIR/scripts/update.sh` regenerates the
  reference from `HEAD` (`--ref origin/main` or a tag for another commit). Uncommitted changes of
  libutils are never part of the reference. After a regeneration, tell the user (the skills repo must be
  committed by them or on request).

## Integration
```cmake
find_package(utils 3.0.0 CONFIG REQUIRED)                      # minimal version
target_link_libraries(${TARGET} PRIVATE utils::utils)          # static lib + include path
```
- Packages (`dnf`/`apt`, see the README `setup.sh`): `libutils` (= `libutils-dev` + `libutils-op`),
  `-db` debug, `-as` asan, `-pre` pre-release; from the sources: `cmake -S . -B build && sudo cmake --build build --target install`.
- Include: **always** the root `#include <utils/utils.hpp>` (preferred; `<utils.hpp>`, `"utils/utils.hpp"`,
  `"utils.hpp"` accepted), never a libutils header one by one (`"utils/network/Server.hpp"`,
  `"utils/attribute/Attribute.hpp"`...). Only a header `utils.hpp` does not give is included directly: the
  observers (`<utils/security/observer/Observer.hpp>`...).
- Sections: every file of a project defines the sections it uses right before the root include
  (`#define _Network`, `_Exception`, `_Cli`, `_Arguments`, `_System`, `_Math`, `_IOManip`, `_SManip`,
  `_Socket`, `_CustomType`, `_Security`...; groups `_Handling`, `_Tools`; nothing defined = everything), in
  a .hpp as in a .cpp. **Mandatory, never a bare include**: `utils.hpp` has no global guard and the defines
  stay set for the rest of the translation unit, so a bare include placed after a partial one only gets the
  sections already defined (missing declarations). Header -> section table: `cpp-class`
  `reference/layout.md` "libutils includes".
- Warnings: `_Warning` enables the deprecation/backward-compatibility/linker/usage warnings,
  `_NoWarning` disables them (`add_definitions(-D_NoWarning)`).
- Linker needs: `Base64Codec`, `AESKey`, `RSAKey` (and `EETPParser`) need OpenSSL (`-lssl -lcrypto`); since
  v3.0.0 the public headers include OpenSSL, `libutils-dev` requires `openssl-devel` / `libssl-dev`.
- License: libutils is MIT, but `algorithms` (c2dmp-hsm, s.o.s) is CC BY-NC-SA 4.0 (non-commercial, see
  `THIRD_PARTY_NOTICES.md`); the RPM license is `MIT AND CC-BY-NC-SA-4.0`.

## Library conventions (to use it the right way)
- Everything is in `utils::<section>` (see the index); a few grouping folders don't add a level
  (`manip/iomanip` -> `utils::iomanip`, `network/socket` -> `utils::network`; `utils::network::socket` is a
  deprecated alias until ~v4.0.0).
- Naming (v3.0.0): public names follow the convention (`autoCast`, `utils::cli::flags`, `isLoaded`,
  `set_style`, `read_mouse_event`, `key_to_string`, `FixedString`, `ConvertibleTo`...); the old names are
  `_migration` aliases until ~v4.0.0: always write the new name, flag the old one when reviewing code.
- Errors: exceptions, never error codes (`throw utils::exception::ErrorException(InternalCode::X, "info")`,
  `catch (const utils::exception::IException& e) {... e.formated() ...}`). Everything about the exception
  classes, the restrictions and adding project codes (JSON + generator + CMake): the `libutils-exception` skill.
- Many APIs take a `failsafe` (warn instead of throw) or `safe_mode` (lock) boolean.
- Check hooks return `std::optional<std::string>`: `std::nullopt` = valid, string = error message
  (`ArgParser`, `Settings`, default hooks `default*ParsingHook`).
- Verbose: `set_verbose(Debug)` (`None`, `Basic`, `Advanced`, `Debug`), then `onBasicVerbose(info)`,
  `onDebugVerbose(info)`, `onVerbose(level, info)`; `*C(output, info)` for another stream, `*Fn(code)` to run code.
- Attribute macros (`_hot`, `_cold`, `_nodiscard`, `_unused`, `_likely`, `_alignas(n)`, `_nonnull(p)`...): given by
  `<utils/utils.hpp>`, always preferred to the raw form (`_alignas(std::hardware_destructive_interference_size)`,
  never `alignas(...)`); `std::hardware_*_interference_size` is guaranteed (fallback 64). Lookup order when an
  attribute is needed: the reference `api/attribute.md`, then the attribute files of the project / system
  (`cpp-class/scripts/list_attributes.sh <project>`), then only the standard `[[...]]` form (`cpp-style`).
- Most classes are non-copyable (`= delete`) and inherit `utils::security::observer::Observer<"Name">`
  (instance tracking for the memory-leak notifier, nothing to do on the user side).

## Section map
| Section | Namespace | What it gives |
|---|---|---|
| `algorithms` | `utils::algorithms::c2dmp`, `::sos` | c2dmp-hsm string distance (`c2dmp<full>(a, b)`), s.o.s steganography (`sos_embed`, `sos_extract`) |
| `arguments` | `utils::arguments` | `ArgParser` (usages, flags, options, env, help), `Settings`/`Setting` (typed settings, casts) |
| `attribute` | macros | compiler attributes per C++ version (`_noreturn`...), `_legacy`, `_migration(x, y, z)` |
| `cli` | `utils::cli` | `Cli` interactive command line (commands, hooks, completion, `Flag`s) |
| `concepts` | `utils::concepts` | operation concepts (`Addable`, `AddableWith`, `Arithmetic`...) and global ones |
| `encapsulation` | `utils::encapsulation` | `Pipe`, `Dup`, `Process`, `Poll` (epoll), `SharedObject` (.so), `SharedMemory` (IPC) |
| `exception` | `utils::exception` | `IException`/`AException`, `Error`/`Warning`/`None`/`Fatal`/`CustomException`, codes |
| `manip` | `utils::iomanip`, `utils::smanip` | ANSI (colors, styles, cursor, mouse), `format`, `FixedString`, `Base64Codec`, `EETPParser` |
| `math` | `utils::math` | geometry (`rotate_point_2D/3D`, `to_look`), trigo (`deg_to_rad`), `CFrame` |
| `network` | `utils::network` | `Server`, `Client`, `ISocket`/`ASocket`/`TCPSocket`, `Address`, `Payload`, `is_ip`, `resolve_*` |
| `pool` | `utils::pool` | `Middlewares<T, U>` chains (before/after), `Cluster` |
| `security` | `utils::security` | `AESKey`, `RSAKey`, `CommonRSAKey`; observers/notifiers (memory leak) |
| `system` | `utils::system` | `IdHandler<T>`, `Scheduler` (delayed tasks), `LoadBalancer<T>` (workers) |
| `type` | `utils::type` | `Vector2/3`, `OVector2/3`, `Matrix`/`OMatrix`, `BidirectionalLookupTable`, `Freezable`, `Worker` |
| `verbose` | `utils::verbose` | verbose levels and macros |
| `root` | `utils` | `utils.hpp` umbrella include, `utils::version` |

## Use libutils instead of rewriting it
In a project that uses libutils (installed **and** `find_package(utils)` / `utils.hpp` in the project), never
write by hand what a section already gives; when reviewing, flag it with the class to use:
| Written by hand | libutils |
|---|---|
| `throw std::runtime_error(...)` and the other standard exceptions | `utils::exception::ErrorException(InternalCode::X, "info")` (`libutils-exception`) |
| `argv[i]` compared / `getopt` | `utils::arguments::ArgParser` (flags, options, usages, env, help) |
| `"\033[31m"`, `"\x1b[0m"` | `utils::iomanip` (`color(Color::Red)`, `set_style({...})`, `reset()`, `file_hyperlink`, `hyperlink`) |
| `socket(AF_INET...)`, `bind` / `listen` / `accept`, `sockaddr_in` | `utils::network::TCPSocket`, `Server`, `Client`, `Address` |
| `pipe`, `dup2`, `fork`, `epoll_*`, `shm_open` + `mmap`, `dlopen` / `dlsym` | `utils::encapsulation::Pipe`, `Dup`, `Process`, `Poll`, `SharedMemory`, `SharedObject` |
| `std::vector<std::thread>` pool, delayed tasks | `utils::pool::Cluster`, `utils::system::Scheduler`, `utils::system::LoadBalancer` |
| id counter + free list | `utils::system::IdHandler<T>` |
| `* M_PI / 180`, `180 / M_PI` | `utils::math::trigo::deg_to_rad` / `rad_to_deg` |
| base64 alphabet / encoder | `utils::smanip::codec::Base64Codec` |
| `if (verbose) std::cout << ...` | `utils::verbose` (`set_verbose(Debug)`, `onBasicVerbose(info)`, `onDebugVerbose(info)`) |
| Levenshtein / edit distance | `utils::algorithms::c2dmp::c2dmp` |
| `[[nodiscard]]`, `[[maybe_unused]]`, `alignas(n)`... | `_nodiscard`, `_unused`, `_alignas(n)`... (`cpp-style` "Attributes") |
| old names (`isloaded`, `auto_cast`, `setStyle`, `utils::network::socket::*`) | new names (`isLoaded`, `autoCast`, `set_style`, `utils::network::*`) |

The checker `xstyle` of this repository (`style/xstyle`, `./setup.sh install xstyle`) enforces this table with its
`LU-*` rules (`xstyle --rtk -c LU`; `LU-INCLUDE`, `LU-SECTION`, `LU-ATTRIBUTE`, `LU-MIGRATION` are fixed by `xstyle --rtk --fix LU`).
Its migration rule reads the `_migration` aliases of the **installed** headers, so it follows the installed version.

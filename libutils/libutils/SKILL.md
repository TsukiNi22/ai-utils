# libutils reference

**Version of this reference: read `reference/VERSION.md` first** (version, commit hash, date).
Everything below `reference/` is generated by `scripts/gen_api.py` from that exact commit.
`SKILL_DIR` = the directory of this file, `LIBUTILS` = `~/personal_delivery/cpp/libutils`.

## How to answer a libutils question
1. `reference/index.md`: find the section / header / namespace of what is needed
   (one table per section, small enough to read entirely).
2. `reference/api/<section>.md`: public API of the headers of that section (signatures,
   default values, trailing comments = documentation). Read only the needed section.
3. Error codes: `reference/exception-codes.md`.
4. Real usage examples: the unit tests of the same commit,
   `git -C LIBUTILS show <commit>:tests/<section>/<file>` (`git -C LIBUTILS ls-tree -r --name-only <commit> tests`),
   and the wiki https://github.com/TsukiNi22/libutils/wiki.
5. Only if the answer is not in the reference: read the header itself at the commit
   (`git -C LIBUTILS show <commit>:include/utils/<path>`) for the implementation details.

## Version checks
- The project may use another version than the reference:
  - required version: `find_package(utils <version> CONFIG REQUIRED)` in the project `CMakeLists.txt`;
  - installed version: `grep __LIBUTILS_VERSION__ /usr/include/utils/version.hpp /usr/local/include/utils/version.hpp`;
  - at runtime: `utils::version` (`std::string_view`, `"vX.Y.Z"`).
- If the version differs from the reference, check the differences before advising an API:
  `git -C LIBUTILS diff --stat v<installed> <commit> -- include` and the CHANGELOG between both
  (removed/renamed APIs are listed in `### Removed` / `### Changed`, migrations keep the old name with a
  `[deprecated ~vX.Y.Z]` marker in the reference).
- New things since the reference: `bash SKILL_DIR/scripts/update.sh --check` (commits, changed headers,
  new CHANGELOG lines since the recorded hash). `bash SKILL_DIR/scripts/update.sh` regenerates the
  reference from `HEAD` (`--ref origin/main` or a tag for another commit). Uncommitted changes of
  libutils are never part of the reference. After a regeneration, tell the user (the skills repo must be
  committed by them or on request).

## Integration
```cmake
find_package(utils 2.14.0 CONFIG REQUIRED)                     # minimal version
target_link_libraries(${TARGET} PRIVATE utils::utils)          # static lib + include path
```
- Packages (`dnf`/`apt`, see the README `setup.sh`): `libutils` (= `libutils-dev` + `libutils-op`),
  `-db` debug, `-as` asan, `-pre` pre-release; from the sources: `cmake -S . -B build && sudo cmake --build build --target install`.
- Include: **always** the root `#include <utils/utils.hpp>` (preferred; `<utils.hpp>`, `"utils/utils.hpp"`,
  `"utils.hpp"` accepted), never a libutils header one by one (`"utils/network/Server.hpp"`,
  `"utils/attribute/Attribute.hpp"`...). Only a header `utils.hpp` does not give is included directly: the
  observers (`<utils/security/observer/Observer.hpp>`...).
- Partial include of `utils.hpp`: define the sections before including it (`#define _Network`,
  `_Exception`, `_Cli`, `_Arguments`, `_System`, `_CustomType`, `_Vector`, `_Matrix`, `_Security`...;
  groups `_Handling`, `_Tools`; nothing defined = everything).
- Warnings: `_Warning` enables the deprecation/backward-compatibility/linker/usage warnings,
  `_NoWarning` disables them (`add_definitions(-D_NoWarning)`).
- Linker needs: `Base64Codec`, `AESKey`, `RSAKey` (and `EETPParser`) need OpenSSL (`-lssl -lcrypto`).

## Library conventions (to use it the right way)
- Everything is in `utils::<section>` (see the index); a few grouping folders don't add a level
  (`manip/iomanip` -> `utils::iomanip`, `network/socket` -> `utils::network`).
- Errors: exceptions, never error codes (`throw utils::exception::ErrorException(InternalCode::X, "info")`,
  `catch (const utils::exception::IException& e) {... e.formated() ...}`). Everything about the exception
  classes, the restrictions and adding project codes (JSON + generator + CMake): the `libutils-exception` skill.
- Many APIs take a `failsafe` (warn instead of throw) or `safe_mode` (lock) boolean.
- Check hooks return `std::optional<std::string>`: `std::nullopt` = valid, string = error message
  (`ArgParser`, `Settings`, default hooks `default*ParsingHook`).
- Verbose: `set_verbose(Debug)` (`None`, `Basic`, `Advanced`, `Debug`), then `onBasicVerbose(info)`,
  `onDebugVerbose(info)`, `onVerbose(level, info)`; `*C(output, info)` for another stream, `*Fn(code)` to run code.
- Attribute macros (`_hot`, `_cold`, `_nodiscard`, `_unused`, `_likely`...): given by `<utils/utils.hpp>`.
- Most classes are non-copyable (`= delete`) and inherit `utils::security::observer::Observer<"Name">`
  (instance tracking for the memory-leak notifier, nothing to do on the user side).

## Section map
| Section | Namespace | What it gives |
|---|---|---|
| `algorithms` | `utils::algorithms::c2dmp`, `::sos` | c2dmp-hsm string distance (`c2dmp<full>(a, b)`), s.o.s steganography (`sos_embed`, `sos_extract`) |
| `arguments` | `utils::arguments` | `ArgParser` (usages, flags, options, env, help), `Settings`/`Setting` (typed settings, casts) |
| `attribute` | macros | compiler attributes per C++ version, `_legacy`, `_migration(x, y, z)` |
| `cli` | `utils::cli` | `Cli` interactive command line (commands, hooks, completion, `Flag`s) |
| `concepts` | `utils::concepts` | operation concepts (`Addable`, `AddableWith`, `Arithmetic`...) and global ones |
| `encapsulation` | `utils::encapsulation` | `Pipe`, `Dup`, `Process`, `Poll` (epoll), `SharedObject` (.so), `SharedMemory` (IPC) |
| `exception` | `utils::exception` | `IException`/`AException`, `Error`/`Warning`/`None`/`Fatal`/`CustomException`, codes |
| `manip` | `utils::iomanip`, `utils::smanip` | ANSI (colors, styles, cursor, mouse), `format`, `fixed_string`, `Base64Codec`, `EETPParser` |
| `math` | `utils::math` | geometry (`rotate_point_2D/3D`, `to_look`), trigo (`deg_to_rad`), `CFrame` |
| `network` | `utils::network` | `Server`, `Client`, `ISocket`/`ASocket`/`TCPSocket`, `Address`, `Payload`, `is_ip`, `resolve_*` |
| `pool` | `utils::pool` | `Middlewares<T, U>` chains (before/after), `Cluster` |
| `security` | `utils::security` | `AESKey`, `RSAKey`, `CommonRSAKey`; observers/notifiers (memory leak) |
| `system` | `utils::system` | `IdHandler<T>`, `Scheduler` (delayed tasks), `LoadBalancer<T>` |
| `type` | `utils::type` | `Vector2/3`, `OVector2/3`, `Matrix`/`OMatrix`, `BidirectionalLookupTable`, `Freezable`, `Worker` |
| `verbose` | `utils::verbose` | verbose levels and macros |
| `root` | `utils` | `utils.hpp` umbrella include, `utils::version` |

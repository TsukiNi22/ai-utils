    MCP toolsOutils MCP

    Every tool of the global session, generated from the code: 79 tools with their parameters.Tous les outils de la session globale, générés depuis le code : 79 outils avec leurs paramètres.

    The global session drives claude-cluster through the MCP server claude-cluster mcp. This page is generated from the tool schemas in the sources (Mcp.cpp, Orchestrator-Control.cpp): the names, descriptions and parameters below are exactly what the model is told. Each tool can be turned off in [mcp_tools] (settings page MCP): <tool> = false.

    A sub-session of the claude driver has its own small MCP with task_*, schedule_* and the job tools only, limited to what it created.

    La session globale pilote claude-cluster par le serveur MCP claude-cluster mcp. Cette page est générée à partir des schémas d'outils des sources (Mcp.cpp, Orchestrator-Control.cpp) : les noms, descriptions et paramètres ci-dessous sont exactement ce que le modèle reçoit. Chaque outil peut être désactivé dans [mcp_tools] (page de réglages MCP) : <outil> = false.

    Les descriptions viennent du code et sont donc en anglais, la langue dans laquelle le modèle les lit.

    Une sous-session du pilote claude a son propre petit MCP avec seulement task_*, schedule_* et les outils de travaux, limités à ce qu'elle a créé.

    1. SessionsSessions

    session_list

    Every session of the cluster: id, name, project folder, backend, state, category, tags, permission mode, tokens, context, cost, pending permissions. Filters: category, tag (one or several, all required), under (a node of the taxonomy: every session below it), state (open: the live ones, default | archived: the trash | all | working, idle...). A category / tag also matches the sessions under the labels below it in the taxonomy (descendants: false: itself only).

    ParameterTypeDescription
    categorystringonly this category (and the ones below it in the taxonomy)
    tagstringonly the sessions with this tag (several: separated by commas; the tags below each included)
    understringevery session under this category / tag node of the taxonomy
    descendantsbooleanfalse: category / tag match themselves only, not the labels below them (default true)
    statestringopen (default) | archived (the trash) | all | a state: working, idle, waiting...

    session_status

    Details of one session and its last 20 messages (skills loaded, files modified).

    ParameterTypeDescription
    session (required)stringid (s1, g) or name of the session

    session_read

    Same as session_status: the last messages of a session.

    ParameterTypeDescription
    session (required)stringid (s1, g) or name of the session

    session_spawn

    Start a new session in a project folder. backend: <provider>[/<model>] (claude, ollama/<model>, openai/<model>, opencode/<provider>/<model>, codex...). For a one-off task set one_shot: true, the session is then archived by itself when it is done.

    ParameterTypeDescription
    cwd (required)stringproject folder (~ allowed), or the name of a project of machine.md (its git repositories: the closest by its name)
    namestringname of the session (default: the folder name)
    backendstringprovider[/model], default from the config
    modestringauto | manual | acceptEdits | plan | dontAsk | bypassPermissions
    profilestringprofile of the config
    promptstringfirst prompt
    replybooleanthe answer to the first prompt (and later wake-up turns) sent back to you as "[reply from ...]" (default true)
    one_shotbooleanthis session is for ONE precise task, never to be reused: closed to the trash (restorable) once its answer is relayed to you (needs reply, and the setting Archive one-shot sessions on; kept when the user typed in it, looks at it or it waits for them). Never for the session of a project you will talk to again (default false)
    effortstringthinking effort: default | low | medium | high | xhigh | max
    contextstringits context at most, compacted past it: 100k to 1M (200k, 500k) or auto (the setting Context at most of the sessions). Size it to the task: a small fix needs far less than a long refactor; every turn and a wake-up after its cache expired cost what it holds

    session_send

    Send a prompt to a session (queued when it is working). By default (reply: true) its answer comes back to you as a message "[reply from <name> (<id>)] ..." when it is done: go on with something else or end your turn, never poll it with session_read / session_status. A local command of claude-cluster (/clear, /model <m>, /mode <m>, /rename, /cd, /close, /cost, /context, /export...) runs at once, as typed in its prompt (no reply): /clear starts a new conversation for the session.

    ParameterTypeDescription
    session (required)stringid (s1, g) or name of the session
    text (required)stringthe prompt
    replybooleanits answer sent back to you when done (default true)
    attachmentsstring[]paths of local files to attach to the prompt (images as pictures, the others as @path): inside the project folder of the session or the home of the user only, no hidden folder; the number is limited by a setting

    session_wait

    Wait until a session is done (up to timeout seconds, 110 max) and get only its last answer (not its context); its outcome tells how its last turn ended - finished, cancelled (interrupted before it finished), error, closed: only finished is done, never take the others as finished: when you need the answer now to go on. A permission waiting is told.

    ParameterTypeDescription
    session (required)stringid (s1, g) or name of the session
    timeoutintegerseconds (default 100)

    ParameterTypeDescription

    session_describe

    Give a session its short description (a few words: what it works on, holds; shown under its name, the trash too, to find it again), its category (ONE word: bugfix, feature, docs, refactor, research, ops...) and its tags (several short words: the topic, the project, the kind of work), the way to find and group sessions (session_list filters, search "#tag"). Set them when you spawn or route a session and keep them true as its topic moves; reuse the ones already in session_list. A text given: kept; empty: claude-cluster writes it again; no text: untouched. category "" removes it; tags replaces all of them, add_tags / remove_tags change some. The user can edit them too; no model is called.

    ParameterTypeDescription
    session (required)stringid (s1, g) or name of the session
    textstringa few words, empty: written again; leave out to keep it
    categorystringone word, "" removes it
    tagsstring[]all its tags (replaces them)
    add_tagsstring[]tags to add
    remove_tagsstring[]tags to remove

    session_fanout

    A request on several sessions / projects at once (a group): a task each, sent as many at once as the parallel sessions allow (the others wait in the task queue); you are woken ONCE with their answers as [group fN ...] to merge them - end your turn after it, never poll. tasks: [{session or cwd, prompt (else the common prompt), after: [indexes of tasks of this group it builds on: their answers given to it]}]; match: {under: folder, has: a file marking a project (default: a git repository), name: part of its name, max} for every project found (its session reused, else created: shown to the user first, then confirmed: true); wait: {mode: all | first | count, count, timeout_minutes (then woken with what came), stop_others (the wait met: the others stopped)}; retry (a failed task tried once more, default true); merge: here (you) | session (a big merge by a session of its own, its answer to you); table: a comparison table asked too.

    ParameterTypeDescription

    promptstringthe common prompt

    matchobject{under, has, name, max}
    waitobject{mode: all | first | count, count, timeout_minutes, stop_others}
    retryboolean
    mergestringhere | session
    tableboolean
    confirmedbooleanthe user agreed to the projects found (match)

    Rewrite the conversation of a sub-session of Claude Code (indexes of session_messages): replace texts, delete messages (a tool call and its result go together), keep only the first N; written as a new conversation (the old one kept), the session started again on it, its transcript shown again.     taxonomy

    The tree of the categories and tags of the sessions: each node (a category or a tag) has an optional parent, none: it hangs under the root "global"; a session hangs under its category, else its first tag. The graph and the grouped list show it nested, session_list filters work on the descendants. action list (default): {parents: {node: parent}, labels: {label: sessions}}; set_parent (node, parent; none or global: the root; a cycle is refused); rename (node, to: also on every session); merge (node, to: the node it joins); delete (node: its children go to its parent; strip: the label also removed from the sessions). Build it as the sessions come: group the tags you reuse (api, ui, db) under one broader node (backend, frontend), not one node per session. Only when the user allowed it (settings: Global session can edit the taxonomy); they edit it by hand too.

    ParameterTypeDescription
    actionstringdefault list
    nodestringthe category / tag to change
    parentstringset_parent: its parent node (none or global: under the root)
    tostringrename: the new name; merge: the node it joins
    stripbooleandelete: also remove the label from the sessions (default false)

    id (requis)stringjob id (j3)
    prio (requis)integer-10..10

# claude-cluster

Run and drive several Claude Code sessions in parallel, one or more per project, from one terminal or one window.
A **global session** manages the others (spawn, prompts, permissions, modes, tasks) through its own MCP server, by
text or by voice. Claude Code is the default agent; Ollama (local), Anthropic-compatible endpoints, OpenAI-compatible
ones (Qwen Code), opencode and the OpenAI Codex CLI work too.

## Installation

Built and installed by the `setup.sh` of the repository, like `xstyle` (binary in `~/.local/bin`, bash / zsh / fish
completion):

```bash
./setup.sh install claude-cluster          # from a clone of ai-utils
curl -fsSL https://raw.githubusercontent.com/TsukiNi22/ai-utils/main/setup.sh | bash -s -- install claude-cluster
./setup.sh remove claude-cluster
```

The completion is generated by `claude-cluster --completion bash|zsh|fish` and installed like the one of `xstyle`:

| Shell | File | Loaded |
|---|---|---|
| bash | `~/.local/share/bash-completion/completions/claude-cluster` | on demand by bash-completion, open shells included |
| zsh | `~/.local/share/zsh/site-functions/_claude-cluster` + the `# >>> tsukini-skills completion >>>` block of `~/.zshrc` | new shells; the command for the current one is printed |
| fish | `~/.config/fish/completions/claude-cluster.fish` (if fish is installed) | on demand, open shells included |

It completes the commands and flags with their description (zsh, fish), and the values: session names and the trash
of the running instance, tasks, providers, backends (`claude/opus`, the local Ollama models as `ollama/<model>` and
`ollama-openai/<model>`, the opencode models), profiles, styles, permission modes, layouts, folders
(`claude-cluster __complete <kind>` gives them as `value<TAB>description`).

By hand: `cmake -S ai/claude-cluster -B build -DCMAKE_BUILD_TYPE=Optimized && cmake --build build --parallel && cmake --install build --prefix ~/.local`.

## Usage

```bash
claude-cluster                          # terminal interface when in a terminal, else a window
claude-cluster --gui                    # window (fails when Qt6 is not built in or there is no display)
claude-cluster --tty --layout grid      # terminal, sessions in a grid (list | grid | tabs)
claude-cluster --backend ollama/qwen3-coder   # backend of the new sessions for this run
claude-cluster --restore | --fresh      # previous run: restore / start new (default: asked, Esc = restore)
claude-cluster --rescan                 # ask at start to sync the map of this computer (even recent or refused)
claude-cluster serve                    # no interface: driven by the commands below and the MCP server
```

Headless commands, on the running instance (`--rtk` compact output for an AI, `--json` raw):

| Command | Effect |
|---|---|
| `list` | sessions: state, backend, tokens, context %, cost, pending permissions |
| `status <s>` | details and the last 20 messages (`<s>`: id, name or name prefix) |
| `spawn [folder]` | new session (`--name`, `--backend`, `--mode`, `--profile`, `--prompt`) |
| `send <s> <text...>` | prompt (queued when the session works; `--force` ignores the budget); a local command (`/clear`, `/model`, `/mode`...) runs as typed in the prompt; not in the prompt history |
| `allow <s> [allow\|always\|deny]` | answer the pending permission |
| `model <s> [model]`, `effort <s> <level>` | model / thinking effort of a session, same conversation (`model <s>` alone: the current one and the choices of its backend) |
| `usage [vendor]` | tokens and cost per vendor (anthropic, ollama, openai...) today / last 7 days / lifetime, the 5 h / 7 d limits left |
| `mode <s> <mode>` | `auto`, `manual` (= `default`), `acceptEdits`, `plan`, `dontAsk`, `bypassPermissions` |
| `interrupt <s>`, `rename <s> <name>`, `cd <s> <folder>` | stop the turn, rename, move to another project |
| `close <s>`, `trash`, `restore <s>`, `purge [s\|*]` | to the trash (kept `trash_days`), list, restore, delete for good (one, the expired ones, `*` all; palette: per session / empty the trash) |
| `task add [--target T] [--after t1,t2] <prompt>`, `task list`, `task cancel <t>` | task queue |
| `schedule add <when> <text> [--target s] [--every N] [--notify]`, `schedule list`, `schedule cancel <w>` | at a time (`+30m`, `+2h`, `HH:MM`, `YYYY-MM-DD HH:MM`), repeated every N minutes or once: a prompt to a session (the global one by default) or a desktop notification |
| `search <text>`, `export <s> [file]` | full-text search in every history, Markdown export |
| `remote on\|off` | Remote Control of the global session |
| `machine sync [--yes]` / `show` / `path` | map of this computer for the global session (asks first, `--yes`: not) |
| `providers`, `notices` | backends and their state, last events |
| `web [on\|off\|pin\|devices]`, `web approve <id> allow\|trust\|deny`, `web kick [ids\|all]`, `web untrust [ids\|all]` | web access on this LAN: its address, its code, its devices (waiting, connected, trusted); open / close it for this run, a new code, a device waiting answered, devices out (all: a new code), trusted no more |
| `external [agent]` | the conversations of the agents opened outside claude-cluster (Claude Code, Codex, opencode, Qwen Code): agent, id, age, folder, title |
| `import <agent> <id> [--name n] [--fork]` | one of them opened here as a session resuming it (its transcript shown); `--fork`: a copy (Claude Code), the original untouched |
| `fork <s> [--name n]` | a copy of a session of Claude Code: its conversation so far, each one goes on apart |
| `engines` | the engines of the voice: what each one handles, its limits, its free use, its links, ready or not (no running instance needed) |

### Prompt

Like Claude Code: **`@`** completes the files and folders of the project of the session (the global session, whose
folder is its own: of the folder claude-cluster was started in, inserted as `~/...` paths), **`/`** the local commands,
the skills and the commands of the agent, then their arguments (`/cd` and `/new` folders, `/mode` modes, `/restore`
closed sessions). In the list: **Tab** completes without validating (into a folder: its content), **Enter** accepts
and closes, **↑ ↓** choose, **Space** / **Esc** close it (`\ ` + Space: a space inside a name).

| Key | Action |
|---|---|
| Enter | send (a local `/command` runs in claude-cluster, any other `/command` goes to the agent); while a turn runs the prompt is **queued** (shown under the transcript); the prompt leaves at once ("sent", "/clear…"): the send and the commands run in the background in their order, an error puts the prompt back |
| Alt+Enter / Shift+Enter | new line (prompt on several lines) |
| Esc | the last queued prompt of the session back in the prompt, removed from the queue (to edit it) |
| Esc / Ctrl+C with voice prompts waiting | drop the last one / all of them (before anything else these keys do) |
| Esc Esc | clear the prompt; on an empty prompt (like Claude Code): the last turn leaves the conversation (claude goes on from the message before it, `--resume-session-at`) and its prompt comes back to be edited (again: the one before) |
| ↑ / ↓ | a line of the prompt; on its first / last line (or empty): the history of the prompts of the session shown, never looped; the prompt being written and the entries changed are kept while browsing (forgotten when a prompt is sent); every way to empty the prompt (send, Esc Esc, Ctrl+C, stash...) starts the browsing again from the newest |
| Ctrl+E | edit the prompt in an editor: `[ui] editor`, else the first installed of nvim, vim, vi, `$VISUAL`, `$EDITOR`, emacs -nw, nano (window: a multi-line dialog); the pasted texts are there in full, the ones left unchanged are blocks again after |
| Ctrl+Z / Ctrl+Y | undo / redo |
| Ctrl+A, Shift+← →, Ctrl+Shift+← →, Shift+Home / End | select all, by character, by word |
| Ctrl+← → , Home / End | move by word, to the start / end |
| Ctrl+X / Ctrl+C / Ctrl+V | cut / copy (with a selection) / paste: text, or an **image** of the clipboard as `[Image #N]` |
| Backspace / Delete / ← → on `[Image #N]`, `[Pasted text #N]` | the whole block at once (one character for the editor, like Claude Code) |
| Ctrl+S / Ctrl+P | stash the prompt / take the last one back (kept over the runs) |
| Ctrl+R | history of the prompts sent to the session shown (type to filter, Enter puts it in the prompt; Tab: every session) |

Local commands: `/cd <folder>`, `/new <folder> [backend]`, `/mode <mode>`, `/rename <name>`, `/close`, `/interrupt`,
`/export [file]`, `/restore [session]`, `/clear` (a new conversation: the transcript emptied, archived in `logs/archive/` for `search`), `/model <name>` (same
conversation, another model), `/cost`, `/context`, `/rewind` (= Esc Esc on an empty prompt), `/exit` (= `/close`),
`/settings`, `/vim`, `/help`; the commands of the agent (`/compact`, skills...) are completed too. A pasted image goes to Claude as an image block (to the
other agents as `@path`). The images are saved by content (`img-<hash>.png`): the same image pasted again (or its chip
clicked) is one more reference to the same `[Image #N]` ("here, here and here"), the image itself is sent once; the
images are numbered in the order of the text when sent.

**Chips** above the prompt, one per image / pasted text of the prompt (dim when removed from the text): mouse over shows
the image (terminal: its pixels as half blocks through `magick`, or the symbols of `chafa` with `[ui] image_preview =
"chafa"`; window: the image itself) or
the pasted text; **click** puts it back in the prompt; **right click** opens the image in the viewer of the desktop
(`[ui] image_viewer`, default `xdg-open`: the real image, outside of the terminal).

**History and stash** keep the images and the pasted texts of a prompt: one taken back (↑, Ctrl+R, Ctrl+P) has its
`[Image #N]` and its `[Pasted text #N]` blocks again.

**Pasted text**: a paste of more than `[ui] paste_lines` lines (3) or `paste_chars` characters (800) is one
`[Pasted text #N +L lines]` block in the prompt (0: never); it is sent, stashed, edited (Ctrl+E) as its full text. In
the terminal the paste of the terminal itself (Ctrl+Shift+V, bracketed paste) arrives in one piece: its new lines don't
send the prompt.

**Vim mode** (`/vim`, the palette, or `[ui] vim = true`): the prompt starts in Insert (`-- INSERT --`), **Esc** goes to
Normal (block cursor, `-- NORMAL --`): `h j k l` / arrows, `w b e`, `0 ^ $`, `gg G`, `f t F T<c>`, `x X s S D C`,
`dd cc yy`, `d c y` + a motion, `p P`, `u` / `Ctrl+R`, `~`, `J`, `r<c>`, counts (`3w`, `2dd`), `v` / `V` visual
(`d x c y ~`), `i a I A o O` back to Insert. In Normal: **Enter** sends, **Esc** with nothing pending does the Esc of the
prompt (queued prompt back, Esc Esc clears), the Ctrl / Alt / F keys stay the shortcuts.

**Transcript** like Claude Code: `⏺` the answers and the tool calls (`Bash(ls)`, `Update Todos` with its ☐ ◼ ☒ list),
`⎿` the first 3 lines of a result (`… +N lines`), `∴ Thinking` folded, the live thinking, and a state line while a turn
runs (`✻ Running Bash… (12s · ↓ 1.2k tokens · Ctrl+C to interrupt)`); **Ctrl+O** unfolds the thinking and the results.
Blank lines between the blocks (prompt, thinking, tool, answer; a result stays with its tool). The **Tokens** panel
tells the new tokens apart from the ones read again from the cache at every step of a turn (`3k +118k cache`: each
tool call reads the whole context again, cheap from the cache). The answers are **typed as they come** (`[ui] typewriter`, `typewriter_speed` characters / s): the agents often send
their tokens in bursts, the text still appears a few characters at a time (faster by itself when a long text is
behind, never more than ~1.5 s late), only what comes while a session is shown: switching to a session shows what it
has at once; `typewriter = false`: shown as received.

Panels of a session (each one enabled per session from the palette): **tokens** (last prompt, current one, total),
**context** (used / window), **cost** (session, last turn, budget, 5 h / 7 d limits), **usage** (the vendor of the
session over every session and run: tokens and cost today, the last 7 days, lifetime - ledger
`~/.local/share/claude-cluster/usage.jsonl` -; the 5 h / 7 d limits left and their reset when the vendor tells them; the
budget left), **skills** (loaded, available), **git** (branch, graph of the commits), **diff** (`git diff --stat` +
diff), **tools** (timeline), **files** (modified).

Model and thinking effort of a session (the same conversation goes on, the session started again): the palette
(*Model: ...* - the Claude aliases and ids, `ollama list`, `opencode models`, the `[models]` of the config - and
*Effort (thinking): ...*), `/model [id]` and `/effort [level]` (completed), `claude-cluster model / effort`, or the
global session (`session_set_model`). Effort: claude `--effort` (low, medium, high, xhigh, max), codex
`model_reasoning_effort`, opencode `--variant`; the default of new sessions is `[agent] effort`.

## Backends

`--backend` / `spawn --backend` / `[agent] default` take `<provider>[/<model>]`:

| Provider | Driver | What | Credentials |
|---|---|---|---|
| `claude` = `anthropic` | claude | Claude Code, its own login (default) | `claude-cluster auth login anthropic` (= `claude auth login`) |
| `anthropic-api` | claude | Claude Code with an API key | key stored by `auth login` |
| `ollama` | claude | Claude Code on a local Ollama model (Anthropic API of Ollama) | none (`ollama serve`, `ollama pull <model>`) |
| `openrouter`, `deepseek`, `kimi`, `zai`, `minimax` | claude | Claude Code on an Anthropic-compatible endpoint | key |
| `openai` | qwen | Qwen Code on the OpenAI API | key |
| `ollama-openai` | qwen | Qwen Code on a local Ollama model (OpenAI API) | none |
| `opencode` | opencode | opencode and its providers (`opencode/<provider>/<model>`) | `opencode auth login` |
| `codex` | codex | OpenAI Codex CLI | `codex login` |
| own `[providers.<name>]` | claude / qwen | any Anthropic- or OpenAI-compatible endpoint (LM Studio, vLLM...) | optional key |
| `groq`, `deepgram`, `elevenlabs`, `cartesia` | voice | the engines of the voice (see [Voice](#voice)), not agent backends | key |

```bash
claude-cluster auth list                 # every provider: ready or not, and why
claude-cluster auth login openrouter     # API key asked without echo, stored in the keyring (secret-tool) or credentials.json (0600)
claude-cluster auth logout openrouter    # key removed (login providers: their own logout)
```

> [!IMPORTANT]
> The **claude** driver is the complete one: one process per session, live permissions in the interface, the MCP
> server, Remote Control. The other drivers start one process per turn (the conversation is resumed with its id):
> their permissions follow the mode (`plan` read-only ... `bypassPermissions`), they can't be asked live.

> [!NOTE]
> Permission modes: the new sessions start in **`auto`** (`[agent] permission_mode`, the classifier of Claude Code
> allows the safe actions, like an interactive Claude Code); `[global] permission_mode` sets the one of the global
> session (default `bypassPermissions`: it never asks, applied at every start). The claude sessions are launched with `--allow-dangerously-skip-permissions` (`[agent] allow_bypass`):
> without it Claude Code refuses to switch to `bypassPermissions` later. The mode shown is the one Claude Code
> confirms; a refused change is shown as an error.

> [!WARNING]
> The cost shown for a non-Anthropic provider through Claude Code is a guess of claude (Claude prices): it is shown as
> `local / unknown`. A small local model may not follow the tools of Claude Code well (7B+ coder models recommended).

## Global session

A session of its own (`[global]`: folder, backend - a claude-driver one -, model) with:
- its **system prompt** `~/.config/claude-cluster/global.md` (written once, customizable: settings page > Global session >
  *System prompt (edit)* opens it in the editor - `[ui] editor`, else nvim, vim, vi... - and starts the session again on
  the same conversation), added to the global `CLAUDE.md` (an empty file: none);
- the **map of this computer** `~/.config/claude-cluster/machine.md`: you (nickname, email, main editor, language of the
  answers, notes: `[user]` of the config, asked at every sync with their current value ready - Enter keeps it - or a
  suggestion: git identity, editors installed, `$LANG`),
  the OS and the hardware (CPU, memory, GPU, disks), the tools and their versions, the shell (aliases: the dangerous
  ones - locking the session, deleting files, powering off... - and the ones replacing a common command, with the
  `\cmd` form to use; functions, PATH, names of the variables), packages, git / GitHub identity, Claude Code config
  (skills, plugins, MCP servers), docker / podman images and containers, folders, language, keyboard, time zone, SSH
  hosts, and the git repositories of the home folder (5 levels, hidden folders skipped: path, kind, branch, origin,
  last activity). Asked at the first start (no: not asked again) and proposed again when older than
  `[ui] machine_days` (30), each time with what is read and stored, y / n; synced from the settings page, the palette
  or `claude-cluster machine sync` (`--rescan` at start: its question forced), its progress in a box in the middle of
  the screen (over any page, Esc hides it) (~5 s: the slow commands run in
  parallel). Local only; the global session reads it for a request about a local project, the user or the system;
- the answer of a sub-session it asked (`session_send`) **comes back to it** as a message `[reply from <name> (<id>)]`
  when the sub-session is done: no polling of `session_read` (each read costs a whole context);
- **notifications** (`[ui] notify`, `notify_global` / `notify_done` / `notify_permission` / `notify_sound`): the end of
  its answers, of the turns of the sub-sessions, a permission waiting; failsafe (no `notify-send`: nothing). See
  [The icon and the notifications](#the-icon-and-the-notifications);
- `/clear` and a new start (`n` at start) only start the context of claude again: the transcript stays, marked
  "new conversation" (the sub-sessions go to the trash as before);
- it **stays**: its process ending by itself (not a stop) starts it again on its conversation (once a minute at most,
  told in the status line);
- the **MCP server** `claude-cluster mcp`: `session_list`, `session_status`, `session_spawn`, `session_send`,
  `session_allow`, `session_set_mode`, `session_interrupt`, `session_close`, `session_restore`, `session_trash`,
  `session_rename`, `session_cd`, `task_add`, `task_list`, `task_cancel`, `search`, `export`, `providers`,
  `session_wait` (until a session is done: its last answer only), `schedule_add` / `schedule_list` / `schedule_cancel`,
  `notify` (a desktop notification), and for
  the interface and itself: `ui_state`, `ui_focus` (show a sub-session while it goes on talking, `g` to come back),
  `ui_layout`, `ui_style`, `ui_panel`, `remote_control` (its own Remote Control), `settings_get` / `settings_set`
  (every option of the settings page), `cluster_info` (version, paths of its files, global session, agents and their
  commands, voice - speech model, models installed, what is missing -, service, interface: no search in its files),
  `config_files` / `config_read` / `config_write` (its own system prompt - it is
  started again on it after its turn -, the one of the sub-sessions, the vocabulary and the words of the voice,
  config.toml checked as TOML before it is written; the map of this computer read only), `machine_sync` (the question
  "Map this computer?" shown in the interface, the user answers it), `session_set_model`, `usage`, `session_display` / `session_display_update` / `session_display_get` (a rich display in a transcript,
  below), `external_conversations` / `session_import` (the
  conversations of the other agents of this computer, opened here), `session_transcript` (whole entries of a transcript),
  `session_context` (a context given to a session: another session, a conversation of an agent, a file),
  `session_messages` / `session_edit` (the real conversation of a sub-session of Claude Code rewritten: texts replaced,
  messages deleted, its end cut) and `session_fork` - these two only when the user allowed them (`[sessions] global_edit`,
  `global_fork`, off by default), `web_access` (the web access:
  address, code, on / off, kick), `voice_engines` (the
  engines of the voice, local and free-tier APIs: languages, strengths, limits, free use, links, ready, used),
  allowed without asking (`--allowedTools mcp__claude-cluster`);
- **questions of the agents** (AskUserQuestion of Claude Code, asked even in `bypassPermissions`): a popup on the
  session shown, like Claude Code / Claude Desktop - the terminal: one question at a time, its options and their
  description, ↑↓ / 1-9, Space ticks (multi choice), Other typed, Enter answers, Esc declines; the window: a dialog
  (radio buttons or check boxes, Other, Answer / Decline); its notice and notification tell the question; the global
  session sees them in `session_status` and answers with `session_allow` `answers` {question: label}; a plain allow
  is refused (the agent would go on without its answer). One question at a time for the whole cluster, shared by the
  keys, the mouse, the voice and the web page: the question of a sub-session is shown on the global session
  (`[sessions] questions_to_global`, on), its own view greyed (*waits for your answer: Ctrl+G*); the voice answers it
  (read aloud with its options when `speak` is on): a number or the label of an option chooses it, a word of `[send]` /
  `[next]` validates it (the next question; the last one: all sent), `[back]` the previous one, `[other] <answer>`
  types it, `[cancel]` declines (`voice-words.txt`). `[sessions] global_answers` (off): the global session is told those
  questions and may choose their answer when it knows what you want;
- **the safety check of Claude Code** (a removal it cannot resolve, `rm -f $O/*.png`...): only a person may approve it.
  A sub-session in `bypassPermissions` asks for it: the global session decides (`[sessions] bypass_to_global`, on; it
  asks you when unsure), you can answer it too. In `auto` mode Claude Code denies it at once without asking: it is then
  shown to you as *safety check* (its reason under it); allowed, the session leaves `auto` for that turn, runs the same
  command again (allowed at once) and goes back to `auto`. The reason of every permission is shown with it;
- **the classifier of the `auto` mode giving no verdict** (a failure on its side, not a refusal): one short line counted
  (×N) instead of its long message each time; two in a row, the session goes to manual mode for the rest of the turn
  (its tools asked to you instead of failing again), then back to `auto`;
- autonomy (from its prompt): what the user asks explicitly is done without asking again; what it decides alone is
  proposed first;
- **Remote Control** (`remote on` / palette): the global session itself on claude.ai and the Claude app (the
  `remote_control` request of Claude Code on its own process): the same claude for both sides, live both ways - what
  is said on claude.ai appears here as it happens, a prompt typed here doesn't stop anything. Its link is shown in the
  header of the global session; it is on again at every start (and after `/clear`, `/model`, a rewind) until
  `remote off`. A background session of the old Remote Control (`claude --bg`) still holding the conversation is
  stopped at start (its conversation kept) and Remote Control goes on in the session itself. A prompt sent from
  claude.ai shows here like a typed one (and goes to the history): claude replays every prompt it gets
  (`--replay-user-messages`), the ones written here carry their own uuid and are not shown twice.

### The MCP page of the settings

`F9 > MCP` (the window: its MCP tab): every tool of the global session with what it does, each one on or off
(`[mcp_tools] <tool> = false`: refused at once with a message for the user, left out of its tool list at its next
start), and the custom MCP servers it gets too (`[mcp] servers`: `"name: command args"` for a local program, or
`"name: https://url"` for an HTTP one; written in its MCP config next to the one of claude-cluster at its next start).

### The icon and the notifications

The settings have a **Notifications** page: all of them on / off, *when* (`unfocused`, default: only when
claude-cluster is not in front, its own popups are; `always`), each kind on / off (the global session, a session
finished, a permission, a question, an error, the limits, the web devices, the task queue, the reminders) and the
sound.

The icon is a stack of terminals whose front one has a face made of prompt characters; the app is `^_^`, and the face
follows what claude-cluster does: the title of the terminal and its bar, the icon of the window, the tab of the web
page, the dock (the number of the sessions waiting on you, else running: the Unity launcher API), `claude-cluster icon
[face] [badge]` (its SVG, for a status bar). The binary installed writes its icon in the icon theme and
`claude-cluster.desktop` (the menu, the dock, the notifications grouped under it).

| Face | The app now | A notification |
|---|---|---|
| `^_^` happy | the global session just answered | the global session answered, a browser connected (web access) |
| `>‿<` grin | a session just finished | a session finished (its tokens), the task queue done |
| `•_•` attentive | a question or a permission waits, the voice listens | a question (its options as buttons), a permission (Allow / Deny), a reminder |

## Voice

`[voice] enabled = true`, then one of three listening modes:

| Mode | Listening | Prompt |
|---|---|---|
| `push` | push-to-talk key (F5: start, F5 again: stop; a sentence ending just after is kept) | every sentence heard while listening |
| `auto` | always, from the start (no key; F5 pauses / resumes) | every sentence heard |
| `wake` | always | only after the wake phrase (`wake_word = "ok claude"`, variants separated by commas): "ok claude, list the sessions" sends it; "ok claude" alone arms the listening `wake_seconds` (optional spoken `wake_reply`) and the next sentence is the prompt |

- The speech model is loaded at the start (about 10 s, `… loading the speech model` in the status line), in every
  mode: F5 listens at once.
- The sentences of one utterance are one prompt (push mode: everything said until F5 closes; auto / wake modes: the
  sentences heard before the confirmation ends). `<session>: ...` goes to that session only for its exact id / name.
- `only_me = true`: only the enrolled voice of the user (`voice-enroll`).
- The prompts of the voice reach the global session marked `[voice]` (its system prompt asks again when a word looks
  misheard); the mark is not shown in the transcript nor kept in the history.
- The transcription is shown `confirm_seconds` before it is sent (palette: send now / drop / correct); the global
  session gets it as `[voice] ...` and asks when a word looks wrong or the request is ambiguous.
- `session <name> <text>` (or `<name>: <text>`) goes straight to that session.
- **Speech model** (`[voice] listen_model`, settings page > Voice; empty: the choice of `voice-models use`):
  `parakeet` (NVIDIA Parakeet TDT 0.6B v3, int8, 640 MB: French, English and both mixed, the text live while speaking -
  the piece being said decoded again every second or so -, the sentence final ~1 s after its end), `whisper` (Whisper
  small int8, 360 MB: slower, 3-6 s, its live text every 3 s or more), `kroko-fr` (the
  French streaming model: live text, the fastest, French only), or the free-tier APIs `groq` / `deepgram` (below).
  `voice-models list | use <m> | install <m>`; changed in the settings, voice-listen starts again on it.
- **Engines** (free or free-tier only; the settings page > Voice shows, for the value chosen with ←→, what it handles,
  its strengths and limits against the others, its free use, its voices and its links; `claude-cluster engines`, MCP
  tool `voice_engines`):

  | Engine | Kind | Where | Languages | Strengths | Limits | Free |
  |---|---|---|---|---|---|---|
  | `parakeet` | speech to text | local | 25 European | best local accuracy, French / English mixed, live text | ~1 s after a sentence, 640 MB | unlimited |
  | `whisper` | speech to text | local | 99 | widest coverage offline | 3-6 s a sentence | unlimited |
  | `kroko-fr` | speech to text | local | French | streaming, fastest, 68 MB | French only | unlimited |
  | `groq` | speech to text | API | 99 | Whisper large-v3-turbo: best accuracy, ~0.5 s | audio sent, no live text | 8 h of audio a day |
  | `deepgram` | speech to text | API | 40+, `multi` mixes 10 | language switched inside a sentence | audio sent, no live text | $200 of credit once |
  | `piper` | text to speech | local | ~40 | instant, light; the fallback of the others | synthetic voices | unlimited |
  | `kokoro` | text to speech | local | 8 (fr: 1 voice) | natural, read sentence by sentence | ~1 s a sentence on CPU, ~600 MB loaded | unlimited |
  | `elevenlabs` | text to speech | API | 32 | very natural, largest voice library | text sent, small quota, non-commercial | ~20k characters a month |
  | `cartesia` | text to speech | API | 42 | fastest (~0.2 s), speed / emotion controls | text sent, credits once, non-commercial | 20k characters once |

  `[voice] listen_model` picks the speech to text, `listen_language` the language spoken (whisper and the APIs; empty:
  found by the model), `say_engine` the text to speech and `say_voices` its voice per language (`fr=ff_siwis,
  en=bf_emma`; `es=kokoro:ef_dora` another engine for a language; missing: the engine's default for it). The language
  of an answer is found from its words (French, English, Spanish, Italian, German, Portuguese, Dutch). The APIs: their
  key by `claude-cluster auth login <groq|deepgram|elevenlabs|cartesia>` (read by voice-listen / voice-tts from the
  keyring or credentials.json, never on a command line, or `$GROQ_API_KEY`...); a failing API (no key, network, quota):
  the sentence recognized by the local model, the answer read by Piper (`voice_fr` / `voice_en`). Kokoro:
  `voice-models install kokoro`; its server (`voice-tts --serve`) keeps the model loaded and ends after 15 min unused.
- **Sentences** (parakeet / whisper): from 0.6 s before the speech is detected (its soft first syllable kept) to
  `[voice] end_silence` of silence after the last voice (default 1.0 s: a short pause, two sentences said in a row are
  one sentence; the cut just after the last voice, never in a word), recognized piece by piece between its pauses (each
  piece its own language: French and English mixed), a speech longer than 30 s cut at a pause. While the user speaks
  ("…", and 2 s after for the end of the sentence) the countdown of a transcription waiting is paused ("paused while you
  speak"), then full again once the new text is added - or sent / dropped at once by a send / cancel word.
- **Said alone while a transcription waits** (compared without case, accent nor punctuation, no wake phrase needed):
  a cancel word ("annule", "stop", "laisse tomber", "cancel"...) drops it, a send word ("envoie", "valide", "vas-y",
  "go", "send"...) sends it at once; nothing waiting, a cancel word stops the answer being read and the turn of the
  global session (only heard while it speaks with `voice-listen --duplex`). The words: `voice-words.txt` of the config
  folder, edited in the editor (settings page > Voice > *Voice words (edit)*, palette *Voice words*), one per line under
  `[cancel]` / `[send]` (`[voice] cancel_words` / `send_words` add more).
- Ctrl+C or Esc stop the reading (an answer read after its turn too, the turn interrupted when it runs); the reading
  stops with claude-cluster (voice-say and its piper | pacat in a group of their own).
- **Vocabulary**: the proper names the recognition bends are written back in every sentence heard, before it is shown,
  routed and sent: the file `vocabulary.txt` of the config folder (`[voice] vocabulary`; settings page > Voice >
  *Vocabulary (edit)*, palette *Vocabulary of the voice*), one name per line with the ways it is heard
  (`libutils = lib utils, lib you tils`), plus by themselves the names of the sessions, the projects of the map of this
  computer and your names (`[user] nickname`, the login). A long name (7+ letters) is also found one or two letters off;
  a common word is never replaced.
- Answers of the global session are spoken as a short summary, in their language (`say_engine`, `say_voices`; Piper:
  `voice_fr`, `voice_en`); F6 stops.
- The palette action **Voice: what is missing** lists what to set up (tools, enrollment, voices, English speech model,
  the model or the API key of the engines chosen).

## Conversations of the other agents

The conversations of the agents of this computer opened outside claude-cluster (Claude Code: `~/.claude/projects`,
Codex: `~/.codex/sessions`, Qwen Code: `~/.qwen/projects`, opencode: `opencode session list`) are offered in the palette
(*Open a conversation of Claude Code: ...*), the web page (*Open a conversation of another agent*), `claude-cluster
external` and to the global session (MCP `external_conversations`). Opened, one becomes a session resuming it in its
folder: its transcript so far shown (the active branch of Claude Code), the same conversation goes on here. A
conversation of Claude Code used less than 2 minutes ago (maybe still open in a terminal) is opened as a copy
(`--fork-session`): the original stays untouched. The ones opened here are not offered again.

- **Fork** (palette *Fork the session*, the web page, `claude-cluster fork <s>`): a copy of a session of Claude Code, its
  conversation so far, then each one goes its own way. The global session may do it only when allowed (settings page >
  Sessions > *Global session can fork*, off by default): to give a new sub-session the context of another one.
- **A context** (MCP `session_context`): the conversation of another session, of an agent, or a file, given to a session
  as a prompt it keeps for its next requests.
- **Edit** (MCP `session_messages` / `session_edit`, only when allowed: *Global session can edit*, off by default): the
  real conversation of an idle sub-session of Claude Code (what its model sees) rewritten - texts replaced, messages
  deleted (a tool call and its result together), its end cut; written as a new conversation next to the old one (kept),
  the session started again on it and its transcript shown again.

## Web access

A browser of the same network (a phone, a tablet, another computer of the LAN) drives claude-cluster: the sessions and
their state, the transcript, a message sent to any session, Stop, the permissions (Allow / Deny) and the questions of
the agents, a new session, a session closed.

- **Views** (its header; a tab bar on a phone): *Chat* (a session and its conversation), *Grid* (every session as a
  card: its state and face, its model and folder, its last messages, its turn, a message sent to it from the card),
  *Board* (your dashboard: tiles moved by drag and drop or ◀ ▶, sized S / M / L, hidden; kept in this browser), *Hub*
  (the global session in the middle, the sessions around it, colored by their state), *Tree* (the sessions by project
  folder). Its colors are the ones of the style of claude-cluster (*This device* may keep its own light / dark).
- **Notifications**: a center (🔔, the notices, unseen ones counted; a click opens the session) and the notifications
  of the browser while the page is not in front (a session finished, waiting for you, an error).
- **Settings** (⚙): every page of the settings of claude-cluster (saved in its config.toml) and *This device* (its
  name, its theme, its view, its voice). A code block clicked: copied.
- **Android app** (`setup.sh install claude-cluster` builds it when the Android SDK is there: `android/build.sh`, no
  Gradle; signed by a key of its own, `~/.config/claude-cluster/android/release.jks`): offered by the page on Android
  (`/app.apk`). The same page in an app: the computer trusted once (its authority pinned after its fingerprint is
  shown: no warning), its notifications, its microphone; a newer app on the computer is offered (never an older one),
  and an app too old for this claude-cluster says so.
- **Completion** like in the terminal: `@file`, `/command`, the argument of `/cd` `/new` `/mode` `/model` `/effort`
  `/restore`, and the folder of a new session (from the home folder); ↑↓, Tab / Enter, Esc.
- **Voice** (⚙ of the page): the microphone of the browser, *tap to talk* or *hands-free* (each sentence cut by its
  silence, `[voice] end_silence`); each sentence recognized by the speech model of the settings (`listen_model`: a
  voice-listen kept loaded, ~10 s the first time) with the vocabulary; it waits `confirm_seconds` (paused while you
  speak, Send now / Cancel / Edit), the cancel / send words act on it. The answers read aloud by the voice of
  claude-cluster (`say_engine`, `say_voices`: a wav from voice-say) or by the voice of the device.

- Open: settings page > Web (`[web] enabled`, opened at every start), the palette *Web access: open*, `claude-cluster
  web on` (this run), `claude-cluster --web`. Its address and its code are shown at the top of the interface:
  `web https://192.168.1.12:8787 · code 123 456 · 2 connected · 1 waiting for you`; a click on it copies the code
  (ready to paste in the page).
- **A 6-digit code**, new at every opening, after 5 wrong ones (each wrong one answered 1 s later) and on a kick of
  every device.
- **Then your approval here** (`[web] approve`, on): the device waits, its popup shows its name (typed in its page,
  else its browser and system), its address and its browser: **Allow**, **Allow and trust** (no code nor approval
  next time), **Deny**, *Later* (the palette: *Web: allow ...*); the notification has the same buttons.
- **Several devices at once**, each one its cookies (bound to its address; 30 s without a request: gone).
- **Web devices** (the palette, the *devices* link of the window, `web devices`): tick devices, then kick them, kick
  all of them (a new code), or remove their trust (the code asked again); trusted devices are kept in
  `~/.config/claude-cluster/web/trusted.json` (0600).
- **This network only**: the browser must have a private address (10/8, 172.16/12, 192.168/16, 169.254/16) of the
  subnet of one of the interfaces of this computer (or be on this computer); the page answers only by the address or
  the name of this computer (a public name pointed at the LAN refused) and the requests of another site are refused.
- From the page: the commands of the sessions (list, read, send, allow, interrupt, spawn, close, rename, mode, model,
  tasks, trash, restore...) and the settings (its settings page); never the web access itself (its devices, its
  trust: here only).
- **HTTPS** (`[web] https`, on by default; built with OpenSSL): an authority of this computer made once in
  `~/.config/claude-cluster/web/` (`ca.pem`, its key 0600), and the certificate of the server signed by it, naming every
  address of this computer (made again when they change, and 30 days before its end). **No browser warning** once the
  authority is trusted by a device: this computer with `claude-cluster web trust-ca` (the palette: *Web access: trust
  its certificate*; the system store, read by Firefox, Chrome and curl; `web untrust-ca` undoes it), the other ones
  from the login page (*trust this computer once*: `/ca.crt` and the steps for Android, iPhone, Firefox, Windows,
  macOS). The code and the conversation are encrypted, and the microphone of the page is allowed (browsers refuse it
  on plain http). A plain `http://` request is sent to `https://`. Off: plain HTTP, no microphone.
- A firewall may have to let the port in (`[web] port`, 8787: `firewall-cmd --add-port=8787/tcp`; the Fedora
  Workstation zone already lets 1025-65535 in).

## Background service

`claude-cluster service enable` installs and starts a systemd user unit (`~/.config/systemd/user/claude-cluster.service`,
started with the graphical session): saying the wake phrase (`[service] wake_word`, else `[voice] wake_word`: "ok
claude") opens claude-cluster with its voice on at once (`--voice auto`, `[service] voice_mode`): `[service] frontend =
"auto"` (default) opens its window when it can (built with Qt6, a display), else - or when the window fails to start -
a terminal (the first installed or `[service] terminal`); `"gui"` the window then a terminal on its failure; `"tty"` a
terminal only. Every try and its failure is in the journal (`service logs`); all of them failed: `FAILED to open`.
(The terminal that has the focus can't be used: GNOME on Wayland tells no one which window it is.)

| Command | Effect |
|---|---|
| `service setup [--debug]` | write the unit and the detector (`~/.local/share/claude-cluster/wake.py`); `--debug`: the unit runs `service run --debug` (setup again without it to stop) |
| `service enable [--debug]` / `disable` | set up and start now (a running one restarted on the new unit) and at every session / stop and not at the next one |
| `service start` / `stop` / `restart` | now only |
| `service status` | installed, active, enabled, DEBUG when it is, an instance running |
| `service logs [--follow]` | its journal (`journalctl --user -u claude-cluster.service`): start, detector, launches and their failures |
| `service remove` | stop, delete the unit and the detector |
| `service run [--verbose] [--debug]` | the loop the unit runs (`--verbose`: the end of the text of every sound; `--debug`: the whole text heard, the levels and the wake events - for the tests only) |

The journal always tells what the service does: its start (wake phrase, front-end, voice), the detector started /
ended by itself (its exit code) and the next try, the detector paused while an instance runs, every wake with the
exact command run, then `claude-cluster started (N ms)`, `failed at its start` with the last lines of its unit
(`claude-cluster-app-<time>-<n>.service`: `journalctl --user -u <unit>`) or `did not answer on its control socket
in 20 s`. Nothing heard is written there out of `--debug`.

- **Light**: the microphone is read all the time, but the speech recognition (the French model of `voice-listen`,
  one thread) only runs on the sounds louder than the background: ~2 % of one core in a quiet room (`voice-listen`
  itself: ~300 %), ~180 MB for the model kept loaded (so the phrase is caught at once).
- The agents run in a session of their own (`setsid`): the signals of the terminal (its tab closed) never reach them,
  claude-cluster stops them itself.
- **One claude-cluster**: while an instance runs (opened by the service or by hand) the detector is stopped (no
  microphone, no CPU); it starts again when the instance quits. The instance is started outside the unit
  (`systemd-run --user`): stopping the service doesn't close it.
- **Privacy**: nothing heard is kept longer than needed: the audio goes through one read buffer and a ring of 0.5 s,
  written over in place and zeroed; the recognition sees at most 3 s at a time; of its text only the last characters
  that can hold the phrase are compared (its length + 10); only the wake event leaves the detector, its buffer zeroed.
- `--voice auto|wake|push` also works by hand: the voice on for this run, whatever the config says.

## Configuration

**Settings page** (F9 or the palette: *Settings*), like a BIOS setup: one tab per section (Interface, Agent,
Commands, Global session, Sessions, Voice, Keys), the help of the selected option on the right, `*` on the changed
ones. Terminal: `↑↓` select, `←→` / `Enter` change a choice / toggle / number, `Enter` edit a text, `Tab` /
`Shift+Tab` section, **Ctrl+S** save (the page stays), **F10** save & exit (when the terminal lets it through),
**Esc** exit: with unsaved changes it asks "Save the changes? (y / n)", y saves, any other key drops them. Window: a
tabs dialog (help on hover, Ctrl+S save, F10 / Save save & close; closed with changes: asked). The changes are written in `config.toml` - only the values, its comments kept - and
reloaded live; the options marked *applied at the next start* need a restart. Profiles, providers and own styles
stay in the file.

`~/.config/claude-cluster/config.toml` (written commented on the first run, reloaded when saved): interface
(`frontend`, `layout`, `style`, default `panels`, `restore = ask | always | never`, `notify`), `[agent]` default backend
and permission mode, `[commands]` of the drivers, `[global]`, `[sessions]` (`trash_days`, `max_parallel` of the task
queue, `budget_usd`, `prompt`: the system prompt of every sub-session, `~/.config/claude-cluster/sessions.md`, an
empty file: none, edited from the settings page or the palette, taken at the next start of each session), `[voice]`, `[keys]`, own `[styles.<name>]` (built-in: `html-light`, `html-dark`, `nord`,
`gruvbox`, `solarized-light`, `mono`), `[profiles.<name>]` (folder, backend, mode, first prompt, extra arguments) and
own `[providers.<name>]`. See [`templates/config.toml`](templates/config.toml).

| Variable | Effect |
|---|---|
| `CLAUDE_CLUSTER_CONFIG_DIR` | config folder (default `~/.config/claude-cluster`) |
| `CLAUDE_CLUSTER_DATA_DIR` | state, trash, history (default `~/.local/share/claude-cluster`) |
| `CLAUDE_CLUSTER_SOCKET` | control socket (default `$XDG_RUNTIME_DIR/claude-cluster/control.sock`) |
| `CLAUDE_CLUSTER_BACKEND` | same as `--backend` |
| `CLAUDE_CLUSTER_RTK` | same as `--rtk` |
| `CLAUDE_CLUSTER_SCREENSHOT` | debug of the window: saves it to this PNG after 3 s then quits (`QT_QPA_PLATFORM=offscreen`); with `CLAUDE_CLUSTER_SCREENSHOT_SETTINGS=1` the settings page too (`<file>-settings.png`) |

## How it works

```
claude-cluster (one per user: control socket)
├── Manager ── Session g (global) ── claude -p --input-format stream-json ... --mcp-config mcp.json
│          ├── Session s1 ── claude -p stream-json (permissions: --permission-prompt-tool stdio)
│          ├── Session s2 ── qwen -p ... -o stream-json -r <id>       (one process per turn)
│          └── Session s3 ── opencode run --format json -s <id>        (one process per turn)
├── Control (unix socket) <── headless commands, claude-cluster mcp (MCP server of the global session)
├── Voice ── voice-listen --json / voice-say
└── front-end: terminal (FTXUI) | window (Qt6) | none (serve)
```

- The agents run through `env -C <folder> VAR=...` (provider environment), every pipe end of the cluster is
  close-on-exec: a session never keeps the pipes of another one.
- History: `~/.local/share/claude-cluster/logs/<id>.jsonl` (search, export, restore); `state.json` keeps the
  sessions (agent session id for `--resume`, cost, tokens), the trash, the tasks and the interface choices.

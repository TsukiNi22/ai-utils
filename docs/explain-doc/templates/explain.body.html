In one sentence: a hash table turns each name into a shelf number, so finding something means going straight to its shelf instead of searching every shelf.

In one sentence: a hash table maps a key to an array index with a hash function, giving O(1) expected insert / lookup as long as the load factor stays bounded.

1. The idea

Think of a coat check with 8 numbered hooks. Instead of hanging your coat anywhere (and searching every hook when you come back), the attendant computes a hook number from your name. When you come back, they compute the same number and go straight to that hook.

The rule that turns a name into a number is called a hash function. If two names give the same number, the second coat goes on the next free hook.

A hash table stores (key, value) pairs in an array of m slots. A hash function h(k) gives the home slot of a key. Two keys with the same home slot collide; this page uses open addressing with linear probing: on a collision, try h(k)+1, h(k)+2, … (mod m) until a free slot.

3. How fast?3. Cost model

The fuller the hooks, the more often the computed hook is taken and the further you walk. On average:

Hooks usedLooks to find a coatLooks to see a coat isn't there
half (50%)1.52.5
most (75%)2.58.5
almost all (90%)5.550.5
That's why real hash tables get bigger (more hooks) before they are too full.

With n keys in m slots, the load factor is α = n/m. Under the uniform hashing assumption, Knuth's analysis of linear probing gives the expected number of probes:

5. Worked example

Type any word: you get its hook number with the simple rule (add the letters) and with a better rule.

Character-sum hash vs polynomial hash h = (31·h + c) mod m, m = 8. Anagrams collide with the first, rarely with the second.

Sum hash
Polynomial hash
Same slot?
std::size_t hash(std::string_view key, std::size_t m)
{
    std::size_t h = 0;

    for (unsigned char c : key)
        h = (31 * h + c) % m;
    return h;
}

6. Common mistakes6. Pitfalls

  • "It's always instant." Only while the table isn't too full (see section 3).
  • "Any rule to make numbers is fine." Adding letters gives "cat" and "act" the same hook.
  • "I can just take a coat away." Emptying a hook can break the search for coats placed after it: tables leave a "was used" marker.
  • Primary clustering: linear probing builds runs of occupied slots that grow faster than the load factor; quadratic probing or double hashing reduce it.
  • Weak hash: structure in the keys (anagrams, multiples of m) maps to the same slots; with untrusted keys, a seeded hash (SipHash) prevents collision attacks.
  • Deletion: clearing a slot cuts the probe chains of later keys: use a tombstone, or backward-shift deletion.
  • Resize cost: a resize is O(n); geometric growth keeps insertion O(1) amortized.

Because when almost every hook is taken, finding a free one (or proving a coat isn't there) takes many looks.By (2), a miss costs 8.5 probes at α = 0.75 and 50.5 at α = 0.9: the cost grows like 1/(1 − α)².
